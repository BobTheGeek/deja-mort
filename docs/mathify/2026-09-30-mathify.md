## Project profile

DÉJÀ MORT is a single-player, offline, die-and-retry room-survival puzzle game in Godot 4.7.2 (GDScript only, ~12.5k lines). You act inside one room while a scripted attacker hunts you; you win by evade, disable, or kill. The only runtime user is the player; the developer is a second user of the `tools/` pipeline. There is no server, database, network, account system, search, user-to-user matching, scheduling, or analytics backend.

The architecture is three layers: `sim/` is pure deterministic logic (seeded `SimRng` only, no `randf`/time — the solver depends on this); `content/` is data-only JSON (1 room, 39 rules, ~40 objects, dozens of tags — tiny, hand-authored); `game/` is presentation, driven off an event bus. `tools/` holds a headless solver, linter, and a per-play JSONL session log read back as counts.

The math already in the codebase is substantial, and none of it was re-recommended: seeded PRNG (`sim/rng.gd`); A* pathfinding + Bresenham LOS + Chebyshev distance (`sim/grid.gd`); 4-connected flood fill for hazard spread (`sim/hazards.gd`); a per-cell spatial hash (`sim/object_store.gd`); a deterministic GOAP planner (`sim/attacker/`); engine AABB/plane hit-testing (`game/room_renderer.gd`, `game/iso_camera.gd`); a bounded action-sequence solver (`tools/solve.gd`). Three concepts from this catalog were added earlier in this session and are now baseline: **spring physics** on the action wheel (`game/wheel.gd`), **simplex noise** for the death flicker (`game/room_renderer.gd`), and **Levenshtein fuzzy matching** in the linter (`tools/fuzzy.gd`).

## Recommendations

None. All 36 catalog concepts were scanned across six parallel passes; every citation was verified against the repo; not one cleared all four gates (evidence, baseline, data, cap). This is the honest result for a deterministic, offline, single-player game with a tiny hand-authored content set: the handful of concepts that ever fit — pathfinding, flood fill, seeded randomness, a damped spring, simplex noise, fuzzy matching — are already implemented. The rest fail because the data they need (traffic, telemetry streams, persisted history, a search corpus, many agents, contested allocation) structurally does not exist here and cannot be acquired without a separate project.

Fewer than three cleared the bar, so there is nothing to build. The rejected table below records why, one line per concept.
